# 03. 객체 검출 — YOLO11 기반 3-클래스 검출

## 과제 정의

주행 환경 영상에서 추출한 이미지에 대해 **vehicle / pedestrian / cycle** 3개 클래스를 검출하는 모델을 학습하고, mAP로 성능을 평가받는 과제였습니다.

| 항목 | 값 |
|---|---|
| 전체 이미지 | 650장 (동일 주행 영상에서 추출) |
| 클래스 | `0: vehicle`, `1: pedestrian`, `2: cycle` |
| 초기 분할 | train 450 / valid 200 |
| 최종 분할 (재구성) | train 430 / val 80 / test 40 |
| 프레임워크 | Ultralytics YOLO11 (n → s) |

**650장은 매우 작은 데이터셋입니다.** 이 전제가 이후 모든 판단의 기준이 되었습니다 — 모델 용량을 키우는 것보다 해상도를 올리는 것이 유리했고, 지표의 노이즈가 커서 작은 차이를 개선으로 착각하기 쉬운 조건이었습니다.

---

## 1단계: 무엇이 병목인지 먼저 측정한다

하이퍼파라미터를 건드리기 전에, **라벨 파일을 전수 파싱해 클래스별 객체 크기 분포를 측정**했습니다. 어떤 클래스가 왜 안 되는지 모르면 튜닝은 추측이 되기 때문입니다.

```python
# src/analyze_dataset.py 참고
from pathlib import Path
import collections

sizes = collections.defaultdict(list)
for lb in Path("data/labels/train").glob("*.txt"):
    for line in lb.read_text().splitlines():
        c, x, y, w, h = line.split()
        sizes[int(c)].append((float(w) * W, float(h) * H))
```

### 측정 결과

| 클래스 | 크기 중앙값 | 32px 미만 비율 | AP50 (초기) |
|---|---|---|---|
| vehicle | 큼 | 0% | 0.96 |
| pedestrian | **약 31px** | **55%** | **0.537** |
| cycle | 중간 | 0% | 변동 큼 (val 인스턴스 18개) |

**결론이 명확했습니다.** pedestrian은 절반 이상이 COCO 기준 "소형 객체(32px 미만)"에 해당하고, 이것이 유일한 실질 병목이었습니다. vehicle은 이미 0.96이라 올릴 여지가 없고, cycle은 검증 인스턴스가 18개뿐이라 수치 자체가 노이즈에 흔들립니다.

→ **입력 해상도(imgsz)를 최우선 레버로 결정.** 소형 객체는 다운샘플링 과정에서 특징이 소실되므로, 해상도를 올리는 것이 가장 직접적인 처방입니다.

---

## 2단계: 해상도 스케일링

가설대로 imgsz를 올릴 때마다 pedestrian AP가 일관되게 상승했습니다.

| imgsz | pedestrian AP50 | 판정 |
|---|---|---|
| 640 | 0.537 | 베이스라인 |
| 768 | 0.617 | 채택 |
| 896 | 0.628 | 채택 |
| 1280 | — | 채택 |
| **1536** | — | **최종 채택** |

1536에서 멈춘 이유는 원본 이미지 해상도를 확인했기 때문입니다. **원본 긴 변이 1536 이하라면 그 이상은 보간(interpolation)일 뿐 정보가 늘지 않습니다.** 실제로 추론 해상도만 1792, 2048로 올려본 결과 mAP50-95가 단조 감소했고, 이는 학습/추론 스케일 불일치로 설명됩니다.

---

## 3단계: 손실 가중치와 옵티마이저

해상도를 고정한 뒤 나머지 레버를 하나씩 검증했습니다.

| 파라미터 | 값 | 근거 |
|---|---|---|
| `optimizer` | AdamW | 소규모 데이터셋에서 SGD 대비 수렴 안정 |
| `lr0` | 0.0007 | 상대 비교로 확정 |
| `box` | 8.5 → 9.0 | 박스 회귀 가중치 상향 시 precision 개선 확인 |
| `dfl` | 1.0 | 명시적 설정만으로 mAP50-95 유의미 상승 |
| `cls_pw` | 0.25 | 클래스 불균형(vehicle 편중) 대응 |
| `cos_lr` | True | 후반 미세 수렴 |
| `close_mosaic` | 25~40 | **아래 설명** |
| `weight_decay` | 0.001 → 0.0075 | +0.0160 mAP50-95 (노이즈의 1.8배) |
| `warmup_bias_lr` | 0.02 | 초기 불안정 완화 |

### close_mosaic — 재현 가능하게 확인된 효과

Mosaic augmentation은 4장을 이어붙여 학습시키는 기법인데, 학습 후반에 이를 끄면(`close_mosaic`) 실제 이미지 분포에 맞춰 미세 조정이 일어납니다. **연속된 3개 run에서 close_mosaic 발동 직후 mAP50-95가 계단식으로 상승하는 패턴이 동일하게 관측**되었습니다. 우연이 아니라고 판단한 근거입니다.

주의점 하나 — `close_mosaic`이 활성인 구간에서는 `patience`에 의한 조기 종료가 마지막 수렴 구간을 잘라먹을 수 있어, patience를 충분히 크게 두거나 0으로 설정했습니다.

---

## 4단계: 모델 크기

마지막으로 남은 레버가 모델 용량이었습니다.

| 모델 | 판단 |
|---|---|
| YOLO11n | 베이스라인 |
| **YOLO11s** | **채택** — batch=12, 나머지 설정 동일하게 유지해 직접 비교 |
| YOLO11m | **기각** — train loss는 계속 내려가는데 val이 평탄한 상태에서 용량을 키우면 일반화 격차만 벌어짐. 650장에 11m은 과함 |

모델을 키울 때는 **다른 조건을 전부 고정**해서 모델 크기만의 효과를 분리했습니다.

## 최종 성능

| 단계 | mAP50 | mAP50-95 |
|---|---|---|
| 베이스라인 (11n, imgsz 1280) | — | 0.6030 |
| imgsz 1536 | — | 0.6567 |
| dfl=1.0, box=9.0, 150 epochs | 0.8818 | 0.6675 |
| weight_decay 0.0075 | — | 0.6870 |
| **YOLO11s + 누수 제거 검증셋** | 0.8694 | **0.6914** |

<sub>※ 데이터 누수 감사 이후 검증셋을 재구성했기 때문에, 위 수치는 서로 다른 검증 조건이 섞여 있습니다. 조건별 정확한 비교는 [04. 실험 로그](04-experiment-log.md)와 [05. 데이터 무결성 감사](05-data-integrity-audit.md)를 참고해 주세요.</sub>

### 남은 한계 — 솔직하게

- **pedestrian은 하이퍼파라미터로는 더 못 올립니다.** 인스턴스 약 280개, 중앙값 23~31px 수준이라 데이터 자체가 병목입니다. 실제 개선 경로는 소형 객체 이미지 추가 수집 또는 타일링 기반 추론입니다.
- **cycle의 수치는 신뢰구간이 넓습니다.** 검증 인스턴스가 18개라 한두 개 검출 차이로 AP가 크게 흔들립니다. 소수점 셋째 자리에 의미를 부여하지 않았습니다.
- **독립적인 외부 테스트셋이 없습니다.** 650장이 모두 같은 주행 영상에서 나왔기 때문에, 다른 도로·다른 카메라 환경에서는 성능 저하가 예상됩니다.

# 05. 데이터 무결성 감사

> 이 문서가 이 프로젝트에서 가장 중요합니다.
> **좋은 숫자가 나왔을 때, 그 숫자를 의심한 기록**이기 때문입니다.

## 발단

튜닝을 거듭한 끝에 mAP50 0.871이라는 괜찮은 수치가 나왔습니다. 그런데 두 가지가 걸렸습니다.

1. **650장 전부가 하나의 주행 영상에서 추출된 프레임**이라는 점 — 인접 프레임끼리는 거의 같은 장면입니다.
2. vehicle 클래스가 **AP 0.96**을 찍었다는 점 — 소규모 데이터셋에서 나오기엔 지나치게 높습니다.

만약 train과 valid에 거의 동일한 프레임이 나눠 들어갔다면, 모델은 **일반화한 게 아니라 본 장면을 다시 본 것**입니다. 그러면 0.871은 발표할 수 없는 숫자가 됩니다.

---

## 검증 1 — Perceptual Hash로 프레임 중복 정량화

파일명이나 순번이 아니라 **이미지 내용 자체**로 유사도를 재야 합니다. 16×16 average hash를 계산하고 Hamming 거리로 비교했습니다.

```python
# src/audit_leakage.py
from pathlib import Path
from PIL import Image
import numpy as np

def ahash(path, size=16):
    a = np.asarray(Image.open(path).convert("L").resize((size, size)), np.float32)
    return (a > a.mean()).ravel()          # 평균 기준 이진화 → 256bit 지문

train_h = np.array([ahash(p) for p in train_files])
val_h   = np.array([ahash(p) for p in val_files])

dist = (val_h[:, None, :] != train_h[None, :, :]).sum(2)   # Hamming 거리 행렬
nearest = dist.min(1)                                       # 각 val 이미지의 최근접 train 거리
```

### 결과 — 심각한 누수 확인

| 지표 | 값 |
|---|---|
| 최근접 거리 중앙값 | **18** |
| 거리 ≤ 5 (거의 동일) | 7 / 200 (3.5%) |
| **거리 ≤ 10 (near-duplicate)** | **34 / 200 (17%)** |
| 거리 ≤ 20 | 113 / 200 (56.5%) |

기준선을 잡기 위해 두 가지를 추가로 측정했습니다.

- **인접 번호 프레임 쌍**의 평균 거리: **28.1**
- **무작위 프레임 쌍**의 평균 거리: **84.9**

즉 최근접 거리 중앙값 18은 "인접 프레임보다도 더 비슷하다"는 뜻입니다. **검증셋의 17%가 학습셋의 near-duplicate였습니다.**

## 검증 2 — 사전학습 가중치가 오염되어 있었다

더 근본적인 문제를 발견했습니다. 실습에서 제공받은 `pre_yolo11n.pt`를 "COCO 사전학습 가중치"로 알고 사용하고 있었는데, 체크포인트 메타데이터를 열어보니 아니었습니다.

```python
import ultralytics          # ★ 커스텀 클래스 unpickling을 위해 torch.load보다 먼저 import
import torch
ckpt = torch.load("pre_yolo11n.pt", map_location="cpu", weights_only=False)
print(ckpt["model"].names)      # {0:'vehicle', 1:'pedestrian', 2:'cycle'}  ← COCO 80클래스가 아님
print(ckpt["train_args"])       # base=yolo11n.pt, epochs=15
```

메타데이터에 **같은 3클래스 이름**과 **저장된 val mAP50 0.6477**이 들어 있었습니다. 즉 이 파일은 COCO 가중치가 아니라 **같은 데이터셋에 이미 15 epoch fine-tuning된 `best.pt`** 였습니다.

### 결정적 확인 — 학습 0스텝 상태에서의 성능 비교

| 가중치 | 학습 0스텝 상태의 val mAP50 |
|---|---|
| `yolo11n.pt` (진짜 COCO) | **0.0009** |
| `pre_yolo11n.pt` (제공받은 것) | **0.7638** |

논쟁의 여지가 없습니다. 학습을 단 한 스텝도 하지 않았는데 0.76이 나온다는 건, 이미 이 데이터셋을 학습한 모델이라는 뜻입니다.

> **이것이 의미하는 바** — 그 전까지의 모든 튜닝 실험은 "성능을 얼마나 올렸는가"가 아니라 **"이미 완성된 모델을 얼마나 덜 망가뜨렸는가"** 를 측정하고 있었습니다. 0.786이라는 초기 최고 기록은 (기존 성능 + 데이터 누수 + 실제 개선분)의 합이었습니다.

## 교정 — 시퀀스 단위 재분할

무작위 분할이 문제의 원인이므로, **연속된 프레임 덩어리 단위로 나누고 경계에 버퍼를 둡니다.**

```python
# src/split_sequence.py
BLOCK  = 60   # 60프레임을 한 덩어리로 묶어 통째로 배정
BUFFER = 10   # 덩어리 경계 앞뒤 10프레임은 버림 (인접 프레임 누수 차단)
```

### 교정 결과

| 지표 | 교정 전 | 교정 후 |
|---|---|---|
| 거리 ≤ 5 (거의 동일) | 7/200 (3.5%) | **0/80 (0%)** |
| **거리 ≤ 10 (near-duplicate)** | 34/200 (17%) | **0/80 (0%)** |
| 거리 ≤ 20 | 113/200 (56.5%) | 8/80 (10%) |
| 최근접 거리 중앙값 | 18 | **34** |
| 최소 거리 | 3 | **16** |
| 최소 프레임 번호 간격 | — | **68** |

**사실상 동일한 프레임 쌍이 완전히 사라졌습니다.**

분할 결과는 `train 430 / val 80 / test 40`이며, 이제 **val은 모델 선택용, test는 최종 보고용**으로 역할이 분리되었습니다.

### 판정 기준을 도중에 수정한 것에 대해

처음에는 "최근접 거리 중앙값 60 이상이면 정상"이라는 기준을 세웠는데, 실제 값은 34가 나왔습니다. 이 기준을 다시 검토한 결과 **이 데이터에는 과하게 엄격한 기준**이었습니다 — 650장 전부가 같은 주행 영상이라 배경·도로·화각이 근본적으로 유사하고, 실제로 **무작위 쌍의 평균 거리조차 84.9**였기 때문입니다. 완전히 다른 순간끼리도 84 수준인 데이터에서 최근접 거리가 84에 근접하는 것은 애초에 불가능합니다.

따라서 판정 기준을 **"near-duplicate(≤10)의 존재 여부"** 로 정정했고, 그 값이 0%가 되었으므로 교정 성공으로 판정했습니다. 남은 8장(거리 ≤20)은 육안으로 확인해 정차 구간이나 유사한 도로 형상 때문임을 확인했습니다.

## 검증 3 — 그래서 0.871은 부풀려진 값이었나?

교정 후 다시 물었습니다. **누수가 실제로 점수를 얼마나 올렸을까?**

기존 val 200장에서 near-duplicate 34장을 제거한 `data_valid_clean`(166장)으로 동일 모델을 재평가했습니다.

| 검증셋 | mAP50 | mAP50-95 |
|---|---|---|
| 원본 val 200장 | 0.8714 | 0.6894 |
| **near-duplicate 제거 166장** | **0.8694** | **0.6914** |

**차이가 거의 없었습니다.** mAP50은 0.002 하락, mAP50-95는 오히려 소폭 상승했습니다.

### 이 결과의 해석

누수가 **존재했던 것은 사실**이지만, 모델이 **그 프레임들을 암기해서 점수를 얻고 있지는 않았습니다.** 이유는 두 가지로 봅니다.

1. 강한 augmentation(mosaic, scale, hsv)이 원본 프레임 암기를 억제
2. near-duplicate라도 객체 위치·크기는 미세하게 달라, 암기만으로는 박스가 맞지 않음

따라서 **0.871은 방어 가능한 수치**로 판정했습니다. 다만 발표에서는 이 검증 과정 전체를 함께 제시했습니다.

## 추가로 발견한 것들

- **라벨 누락 3장** (train 430장 중 라벨 파일 427개) — 파일 번호 103, 196, 797. 육안 확인 결과 셋 다 차량과 보행자가 있는 장면이었으므로 **빈 배경이 아니라 라벨링 누락**으로 판정했습니다. (YOLO는 라벨 없는 이미지를 배경으로 취급해 오검출을 줄이는 순기능도 있지만, 실제 객체가 있는 경우엔 학습 신호를 잃는 손해입니다.)
- **`data_seq`의 2차 오염** — 재분할된 `data_seq/val`, `data_seq/test`가 각각 기존 `data/train`과 79%, 70% 파일명이 겹쳤습니다. 같은 650장 풀을 다시 나눈 것이므로 **현재 모델은 그 이미지들을 이미 학습에서 봤다**는 뜻입니다. 이 split에서 나온 mAP50 0.965, 0.991 같은 수치가 비정상적으로 높았던 이유가 여기 있었습니다. → 최종적으로는 `yolo11s.pt`(순수 COCO)에서 시작해 `data_seq`만으로 재학습하는 경로를 택했습니다.

## 이 감사가 만든 차이

발표에서 쓸 수 있는 문장이 이렇게 바뀌었습니다.

| 감사 전 | 감사 후 |
|---|---|
| "mAP 0.871을 달성했습니다" | "이미지 해시로 인접 프레임 누수를 정량 검출(거리 ≤10이 17%)하고, 시퀀스 단위 재분할로 0%까지 교정한 뒤, 누수 제거 검증셋에서 0.869를 재확인했습니다. 또한 제공된 사전학습 가중치가 순수 COCO가 아님을 메타데이터와 0스텝 성능(0.0009 vs 0.7638)으로 확인했습니다." |

앞 문장은 누구나 씁니다. 뒤 문장은 **검증 역량이 드러납니다.** 심사위원이 연구원이라는 점을 고려하면, 이 차이가 수상에 가장 크게 기여했다고 생각합니다.

# 04. 실험 로그

## 실험 원칙

성능 튜닝을 시작하기 전에 세 가지 규칙을 먼저 정하고 끝까지 지켰습니다. 짧은 기간에 많은 실험을 돌릴수록, 규칙이 없으면 **"어떤 변경이 효과가 있었는지 알 수 없는 상태"** 로 끝나기 때문입니다.

### 1. 한 번에 하나의 변수만 바꾼다

두 개를 동시에 바꾸면 개선이 나와도 원인을 특정할 수 없습니다. 실제로 이 원칙이 깨진 사례가 한 번 있었는데(`weight_decay` 변경과 함께 `workers`가 0→2로 바뀜), **augmentation의 난수 스트림이 달라졌기 때문에 순수한 weight_decay 효과라고 단정할 수 없다**고 기록에 남겼습니다.

### 2. 재현성 고정

```python
seed = 42
deterministic = True
```

### 3. 노이즈 하한을 먼저 측정하고, 그보다 작은 차이는 개선으로 보지 않는다

같은 설정으로 반복 실행했을 때의 변동폭을 측정한 결과 **σ ≈ 0.0089 (약 ±0.9%p)** 였습니다. cycle 클래스는 검증 인스턴스가 18개뿐이라 개별 클래스 AP의 노이즈는 ±1.5%p 수준까지 벌어집니다.

> **채택 기준: 개선폭이 노이즈의 1.5배 이상일 때만 채택.**
> 이 기준이 없었다면 "0.6675 → 0.6690" 같은 변화를 개선으로 착각해 잘못된 방향으로 갔을 겁니다.

## 기각된 실험 — 그리고 그 이유

**기각 기록이 채택 기록만큼 중요합니다.** "안 되는 것을 왜 안 되는지 알고 배제했다"는 것이 실험 설계 역량의 근거이기 때문입니다.

### TTA (Test-Time Augmentation) — 기각

```python
model.val(augment=True)   # → mAP50-95 0.6635 (기존 0.6675 대비 하락)
```

일반적으로 TTA는 공짜로 0.5~1.5%p를 얻는 기법으로 알려져 있는데, 여기서는 **오히려 성능이 떨어졌습니다.**

**메커니즘** — TTA는 원본 외에 축소된 스케일로도 추론해 결과를 앙상블합니다. 그런데 이 데이터셋의 병목은 pedestrian(55%가 32px 미만)이고, 축소 패스에서는 이 소형 객체들이 사실상 소실됩니다. 손실이 이득을 넘어선 것입니다.

> 교과서적으로 좋다고 알려진 기법도 **데이터 특성에 따라 역효과**가 날 수 있다는 사례. 발표에서 이 부분을 설명했을 때 반응이 좋았습니다.

### 추론 해상도 스케일링 (1792 / 2048) — 기각

| 추론 imgsz | mAP50-95 |
|---|---|
| 1536 (학습과 동일) | 최고 |
| 1792 | 하락 |
| 2048 | 더 하락 |

**단조 감소**했습니다. 원인은 학습/추론 스케일 불일치 — 모델은 1536 스케일의 특징 분포에 맞춰 학습되었기 때문에, 추론 시 해상도를 바꾸면 앵커·특징 스케일이 어긋납니다.

### YOLO11m으로 확대 — 기각

train loss는 계속 하강하는데 val이 평탄한 상태였습니다. 이 상황에서 모델 용량을 늘리면 일반화 격차만 벌어집니다. 데이터 650장에 11m은 과합니다.

## 과적합 진단

최종 run(150 epochs)의 학습 로그를 분석해 일반화 격차를 정량화했습니다.

| epoch | val/train box loss 비율 | val/train cls loss 비율 |
|---|---|---|
| 20 | 1.07× | — |
| 150 | **1.68×** | **2.34×** |

또한 **mAP50은 epoch 20 이후 사실상 포화**되었습니다 (이후 130 epoch 동안 순변화 −0.007).

### best.pt의 낙관 편향

`best.pt`는 전 epoch 중 검증 성능 최대값 시점의 가중치입니다. 즉 **노이즈가 위쪽으로 튄 순간을 고를 수밖에 없는 구조**입니다.

- best.pt 선택 시점: epoch 134
- 추정 편향: 약 +1.9σ
- 실제 기대 성능: 0.665 ~ 0.670 수준

이 값을 발표에서 함께 제시했습니다. `best.pt`와 `last.pt`를 둘 다 재평가해 편향 크기를 직접 측정한 뒤, **"우리가 보고하는 0.667은 이 정도의 낙관 편향을 포함한다"** 고 명시한 것이 심사에서 신뢰도로 작용했습니다.

---

## 이 로그가 남긴 것

성능 수치 하나보다, **"어떤 순서로 무엇을 시험했고 왜 그렇게 판단했는가"** 라는 서사가 그대로 발표 자료가 되었습니다.

```
병목 측정(소형 객체 55%) → 처방(해상도) → 검증(단조 상승)
   → 다른 레버 순차 검증 → 노이즈 하한 기준으로 채택/기각
      → 기각 사유까지 메커니즘으로 설명
         → 남은 편향(best.pt 낙관 바이어스)까지 스스로 공개
```
